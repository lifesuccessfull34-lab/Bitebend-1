Phase 6 — WhatsApp Bill Delivery + Session-Based Screenshot Verification

Goal:

Complete the payment workflow for session-based billing.

Current situation:

* Active Sessions exist.
* Bills can be generated.
* session_bills table exists.
* Session status changes:
  active → awaiting_payment

Now implement payment collection and manual verification.

IMPORTANT ARCHITECTURE RULE

Payment screenshots must be stored against the Session Bill.

NOT against individual orders.

Database ownership:

Session
→ Session Bill
→ Payment Screenshot

However, in the Dashboard UI, the screenshot and verification controls must appear directly inside the corresponding Session Card so restaurant staff never need to search a separate queue.

---

PART A — WhatsApp Bill Sending

1. Add a "Send Bill" button on billed sessions.

2. When clicked:

* Use existing WhatsApp Bridge
* Send one bill message per session

Message should include:

* Bill Number
* Table Number
* Total Amount
* Payment QR
* Payment Instructions

3. After successful send:

session_bill.status

generated
→ sent

4. Store:

* sentAt timestamp

---

PART B — Screenshot Collection

1. Customer sends payment screenshot to restaurant WhatsApp.

2. WhatsApp Bridge receives image.

3. Screenshot must attach to the Session Bill.

NOT to individual orders.

4. Update:

session_bill.status

sent
→ awaiting_verification

5. Store:

* screenshotUrl
* receivedAt

---

PART C — Session Card Verification UI

DO NOT create a separate Payment Verification Queue.

Instead:

When a screenshot is received:

The corresponding Session Card should display:

* Screenshot Received badge
* Awaiting Verification badge
* Screenshot thumbnail
* Received time

Example:

Table T3

Awaiting Verification
📸 Screenshot Received

Bill #1001
₹2,350

---

PART D — Expanded Session View

When a session is expanded:

Show:

* All orders in the session
* Screenshot thumbnail
* View Screenshot button
* Approve Payment button
* Reject Payment button

Restaurant staff should verify payment directly from the Session Card.

They should never need to search another page or queue.

---

PART E — Approve Payment

When owner clicks Approve:

session_bill.status

awaiting_verification
→ paid

table_session.status

awaiting_payment
→ closed

All orders inside the session:

paymentStatus
→ paid

Store:

* verifiedAt
* verifiedBy

---

PART F — Reject Payment

When owner clicks Reject:

session_bill.status

awaiting_verification
→ sent

Screenshot remains attached.

Owner can wait for another screenshot from the customer.

---

Session Card lifecycle:

Active Session
↓
Generate Bill
↓
Awaiting Payment
↓
Send Bill

---

Do NOT Implement

* OCR
* AI verification
* Automatic payment matching
* UTR extraction
* Payment amount detection

Manual verification only.
