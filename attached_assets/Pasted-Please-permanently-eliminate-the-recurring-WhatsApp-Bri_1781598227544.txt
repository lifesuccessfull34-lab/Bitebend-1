Please permanently eliminate the recurring "WhatsApp Bridge unreachable" issue on fresh GitHub imports.

Current problem:
A new Replit account imports the repository successfully, but the WhatsApp Bridge is not running or not configured, causing the portal to show:

"WhatsApp Bridge unreachable. Make sure the bridge service is running"

Requirements:

1. Auto-start the WhatsApp Bridge whenever the application starts.

   * The bridge should be part of the normal startup workflow.
   * No manual bridge startup should be required.

2. Add bridge health checks.

   * Create a startup check that verifies the bridge is reachable.
   * Log a clear error if the bridge fails to start.

3. Auto-detect Chromium.

   * Do not rely on hardcoded Chromium paths.
   * Automatically locate Chromium in the environment.
   * Use PUPPETEER_EXECUTABLE_PATH only as an override.

4. Add bridge readiness checks.

   * Wait for the bridge to become healthy before reporting the application as ready.

5. Add automatic bridge recovery.

   * If the bridge process crashes, restart it automatically.
   * If the bridge is unavailable, show diagnostics instead of a generic error.

6. Add a setup verifier command:
   pnpm doctor

   The command should verify:

   * Database connection
   * API server
   * WhatsApp Bridge
   * Chromium availability
   * Required environment variables

7. Add startup diagnostics:

   * Display whether the bridge is running.
   * Display Chromium path being used.
   * Display bridge URL and port.

8. Update documentation with:

   * Fresh install steps
   * Bridge troubleshooting steps
   * Expected startup logs

9. Verify that a completely fresh GitHub import on a new Replit account can:

   * Start successfully
   * Launch the bridge automatically
   * Reach the bridge health endpoint
   * Show "Connected" status in the portal without manual intervention

10. If WhatsApp authentication is not yet completed, show:
    "Bridge running – WhatsApp QR authentication required"

    instead of:
    "Bridge unreachable"

The goal is that a fresh GitHub import should never require manual bridge setup or debugging.
