Current WhatsApp payment flow is incorrect and must be redesigned.

PROBLEM:

Current flow:

Dashboard → Send Payment Bill
→ QR bill image generated
→ file downloads to restaurant device
→ restaurant manually uploads image to WhatsApp

This is not usable for real restaurant operations.

The system is still sending text as the primary message while forcing manual image sharing.

We want FULLY AUTOMATED WhatsApp bill delivery.

---

NEW REQUIRED FLOW

Dashboard
→ Click "Send Payment Bill"
→ Backend generates payment bill with embedded QR
→ QR contains prefilled payment amount + order reference
→ Bill image/PDF automatically sent directly to customer WhatsApp
→ No local download
→ No manual attachment
→ No "Share Again" workflow

Restaurant staff should click only ONE button.

---

IMPLEMENTATION REQUIREMENTS

STEP 1:

Move QR generation from frontend to backend.

Create endpoint:

POST /api/bills/send-whatsapp-payment

Input:

{
orderId,
customerPhone
}

Backend should generate:

* payment bill image or PDF
* QR code with prefilled amount
* restaurant details
* table
* items
* total
* order reference

Do not generate bill in browser.

Generate on server.

---

STEP 2:

QR must contain dynamic payment details:

Example:

amount=₹500
merchant=Restaurant Name
reference=Order123

QR should open:

UPI payment app
with amount already filled

Customer only scans and pays.

---

STEP 3:

Do NOT download files locally.

Remove:

downloadBill()
saveToDevice()
shareAgain()
manual attachment logic

Remove any browser-download based flow entirely.

---

STEP 4:

Use WhatsApp media delivery instead of text-only sharing.

Current system behavior:

Text:
"Please find attached payment bill..."

This is wrong.

New behavior:

Send IMAGE/PDF attachment as PRIMARY WhatsApp message.

Message should include:

Hi {customerName},

Please complete payment using attached QR bill.

Total: ₹{amount}
Table: {table}
Reference: Order #{orderId}

Scan QR and pay using UPI.

Attachment:
[payment-bill-with-embedded-QR]

---

STEP 5:

Implement server-side WhatsApp media sending.

Possible architecture:

Backend generates file
→ uploads temporary media
→ sends image/document directly

No client-side file handling.

No browser share API.

No local folder usage.

---

STEP 6:

Fallback logic:

If WhatsApp media send fails:

show:

"Unable to send payment bill"

Do NOT silently download files.

---

STEP 7:

Preserve existing bill design.

Only change delivery mechanism.

End goal:

Restaurant clicks one button
→ customer instantly receives QR bill image directly inside WhatsApp chat
→ amount already prefilled
→ no downloads
→ no manual upload
→ no extra steps

This is mandatory for production restaurant operations.
