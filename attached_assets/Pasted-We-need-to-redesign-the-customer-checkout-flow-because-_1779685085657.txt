We need to redesign the customer checkout flow because the payment architecture has changed.

Current flow assumptions are outdated.

Previously:

Place Order
→ automatic processing
→ WhatsApp payment bill later

Now:

Customer should explicitly choose payment mode before order placement.

Do a checkout redesign.

==================================================

NEW FLOW

Cart
→ Checkout
→ Select payment option
→ Order confirmation screen
→ Menu

No automatic transitions.

==================================================

STEP 1 — REDESIGN CHECKOUT PAGE

On checkout page add a dedicated section:

"Choose Payment Method"

Create two large buttons/cards:

Button 1:

Cash Payment

icon:
cash / currency

description:

Pay directly at restaurant counter/table

---

Button 2:

Scan QR & Pay and Proceed

icon:
QR / UPI

description:

Scan QR and complete payment before placing order

---

Selection should visually highlight:

selected state
border
background
check icon

Do not use dropdown.

Use card layout.

==================================================

STEP 2 — ORDER CONFIRMATION SCREEN

After placing order:

Show confirmation page (current Image2 equivalent)

BUT:

Remove automatic redirect to menu page.

Current behavior:

Order success
→ auto redirect

Remove entirely.

Customer must remain on confirmation screen.

Add footer navigation:

[ Previous ]     [ Next ]

Behavior:

Previous:
returns to previous page

Next:
opens main menu

No automatic transitions.

==================================================

STEP 3 — PAYMENT AWARE ORDER STATUS

When Cash selected:

paymentMode = CASH
paymentStatus = PENDING

When Scan QR selected:

paymentMode = ONLINE

Do not finalize online payment unless payment confirmed.

==================================================

STEP 4 — CUSTOMER ORDER HISTORY

Customers currently have no way to see previous orders.

Create new page:

/orders
or
/order-history

Add button on customer UI:

"My Orders"

Store order history using:

phone number
session
customer identifier

Show:

Restaurant
Date
Order ID
Items
Total
Payment Method
Payment Status
Order Status

Examples:

Paid
Pending
Cash
Preparing
Completed

Newest first.

==================================================

STEP 5 — ORDER HISTORY DETAIL PAGE

Clicking order:

show:

items
table
subtotal
payment status
bill link (if exists)

future ready for:

Track Order
Reorder

==================================================

STEP 6 — DO NOT BREAK EXISTING FLOWS

Preserve:

cart
table handling
restaurant ordering
WhatsApp bill system
payment architecture

Only redesign checkout and customer experience.

==================================================

Goal:

Customer journey becomes:

Browse menu
→ cart
→ choose payment type
→ place order
→ confirmation screen
→ optionally return menu
→ later open My Orders

No hidden redirects.
